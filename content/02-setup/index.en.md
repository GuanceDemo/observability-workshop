## Environment Setup

This chapter completes the foundational environment configuration from scratch to observable:

1. Declare EKS and DataWay parameters, and install DataKit using Helm.
2. Create a Web RUM application in Guance and record the Application ID and Workspace ID.
3. Deploy the microservice mall to EKS using public images and obtain the public access URL.

Parameters that require user input are DataWay URL, RUM Application ID, and Guance Workspace ID. `project=mall-demo`, image tag `2.3.5`, Namespace, and Demo internal passwords are fixed or auto-generated by the tutorial.

### Quick Setup (Optional)

If you already have an EKS cluster with a Ready EC2 worker node, use the quick path to install DataKit and the Demo. The existing step-by-step tutorial remains available for configuration details and troubleshooting.

#### 1. Prepare Platform Parameters

Complete the following preparation in the [Guance console](https://console.guance.com/):

1. Go to **Integration → DataKit → Kubernetes(Helm)** and copy the full `datakit.dataway_url` value.
2. Go to **RUM → Application → Create**, create a Web RUM application, and copy its **Application ID** and the current workspace's **Workspace ID**.

Open AWS CloudShell and declare all parameters required by the quick setup. CloudShell supplies the current Region automatically. The DataWay URL contains a sensitive token; hidden input prevents it from entering shell history:

```shell
export EKS_CLUSTER_NAME="eks-demo-cluster"
read -rsp 'DataWay URL: ' DATAWAY_URL && export DATAWAY_URL && echo
read -rp 'RUM Application ID: ' RUM_APPLICATION_ID && export RUM_APPLICATION_ID
read -rp 'Guance Workspace ID: ' GUANCE_WORKSPACE_ID && export GUANCE_WORKSPACE_ID
```

#### 2. Run the Quick Installation

Clone the pinned release from the official Guance repository and run the installer from the repository root:

```shell
export DEMO_VERSION="2.3.5"
git clone --branch "v${DEMO_VERSION}" --depth 1 \
  https://github.com/GuanceDemo/observability-demo.git
cd observability-demo

scripts/workshop.sh install
```

If Helm is unavailable, the script installs and verifies Helm `v3.17.3`. It displays the AWS identity, target Kubernetes context, and nodes, then installs DataKit `2.5.0` and all six Demo workloads after confirmation and waits for a public Gateway hostname or IP. For automation, use `scripts/workshop.sh install --yes` to skip confirmation.

If the `datakit/datakit` Helm Release already exists, the script stops by default to avoid overwriting shared configuration. Use the following step-by-step chapters instead. Only when you have confirmed that the existing DataKit may be upgraded should you explicitly run `scripts/workshop.sh install --upgrade-existing-datakit`.

After a successful installation, the script prints `DEMO_BASE_URL` and the SourceMap version reminder. It does not run smoke tests, generate traffic, or inject faults. Clear the parameters from the current shell:

```shell
unset DATAWAY_URL RUM_APPLICATION_ID GUANCE_WORKSPACE_ID
```

Next, complete **Create RUM Client Application → Step 3: Prepare SourceMap Files**, then continue to chapter 3 for observation and fault demonstrations. Continue with the following step-by-step chapters whenever you need the complete deployment process or troubleshooting details.
